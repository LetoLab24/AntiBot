# AntiBot gate — привратник для сайта на обычном хостинге

Сторож AntiBot читает журнал nginx и банит через nginx — для этого нужен свой сервер и root. На обычном хостинге (Beget, Timeweb, Спринтхост и т. п.) root нет, а журнала посещений часто нет совсем. Для них — привратник: небольшой PHP-файл, который выполняется перед каждой страницей сайта.

Что он делает:
- **закрывает адреса из списка** — страница «Доступ временно ограничен» с вашим контактом, сайт и база не запускаются;
- **ведёт свой журнал** — одна строка на запрос, 14 дней;
- **ставит метку JS** — в страницы вставляется строка со скриптом. Браузер выполняет скрипт и получает куку-метку, программа без браузера — нет. Метка привязана к сети посетителя (/24, IPv6 /48) и действует 7 дней;
- **сканеров закрывает сам**: 3 пробы за час (`/.env`, `/.git`, `phpinfo.php`…) или одна SQL-инъекция — бан на 30 суток, не дожидаясь хаба;
- **проверка браузера** (выключена по умолчанию): адресу без метки сверх порога страниц за час — короткая страница, которая выполняет скрипт и сама открывает сайт;
- **связь с хабом** (если подключён): раз в минуту, после ответа посетителю, отдаёт подозрительные адреса и забирает список банов и настройки. Отдельный cron не нужен;
- **связки примет** (с 0.2.0): закрывает запрос, только когда совпали сразу несколько примет — имя браузера, откуда пришёл (Referer), адрес страницы, метод. Так закрываются боты, которые ходят под обычным именем, но с подставным поисковиком в Referer;
- **свои правила сайта** (с 0.2.0): файл `my-rules.php` — адреса, сети, имена и связки, которые сайт закрывает сам. Действуют сразу; хабу уходят только предложением;
- **страница состояния** (с 0.2.0): `/?abg=s&k=КЛЮЧ` — что берёте из общего списка, что сработало за час, ваши правила и решения по вашим предложениям.

Из хаба приходят **только данные**: адреса, сети, имена браузеров, связки примет, пороги, вкл./выкл. проверки браузера, шаблоны адресов страниц. Код из хаба не приходит и не выполняется никогда. Список подписан ключом хаба — неподписанный или изменённый в пути не принимается.

## Что решает сам сайт

Что брать из общего списка, решает сайт в `config.php`, строка `shared` — хаб это не переопределит:

| Группа | Что это |
|---|---|
| `bans` | адреса сканеров и ботов, ручные баны |
| `nets` | сети хостингов, откуда не ходят люди |
| `names` | имена браузеров сборщиков |
| `seo` | SEO-роботы (Ahrefs, Semrush и т. п.) — выключите, если сами ими пользуетесь |
| `patterns` | связки примет |

Значения: `on` — закрывать, `watch` — только отмечать (в журнале и на странице состояния видно, кого закрыл бы и сколько из них выполнили скрипт страницы, то есть похожи на людей; сайт работает как раньше), `off` — не брать. Связка из хаба приходит со своим режимом: новая — только отмечает. Закрывать она будет, только если и хаб, и сайт сказали `on`.

Белый список (`allow`) сильнее всего, в том числе ваших правил.

## Что нужно

- PHP 7.0 или новее. Других расширений и библиотек не нужно.
- Расширение `openssl` — чтобы принимать подписанные списки хаба (оно есть почти на всех хостингах). Без него привратник работает сам: свой журнал, метка, бан сканеров.
- `curl` желательно; без него связь с хабом идёт через `file_get_contents`.

## Установка

1. Загрузите папку `antibot-gate` (файлы `gate.php`, `mark.js`, `data.htaccess`, `sync.php`, `config.example.php`, `my-rules.example.php`) **на уровень выше корня сайта** — рядом с `public_html`, а не внутрь. Так журнал и настройки нельзя открыть из браузера.
2. Скопируйте `config.example.php` в `config.php` и впишите:
   - `domain`, `contact` — для страницы бана;
   - `engine` — `wordpress` (и WooCommerce), `opencart`, `bitrix` или `custom`;
   - `secret` — случайная строка от 32 символов (`php -r 'echo bin2hex(random_bytes(24));'`);
   - если вам дали подключение к хабу — `hub_url`, `site_token`, `hub_public_key`;
   - `allow` — адреса офиса, 1С, CRM, агрегаторов, которым вы отдаёте фид;
   - `shared` — что брать из общего списка (см. выше);
   - `status_key` — случайная строка от 16 символов для страницы состояния.
   Папка `data` создастся сама — у PHP должно быть право записи в `antibot-gate`.
   Свои правила — скопируйте `my-rules.example.php` в `my-rules.php` (при обновлении привратника его и `config.php` не заменяйте).
3. Подключите привратник **одним** из способов:

| Способ | Как | Когда |
|---|---|---|
| **А. `auto_prepend_file`** — лучший | файл `.user.ini` в корне сайта: `auto_prepend_file = /home/ЛОГИН/site/antibot-gate/gate.php` (PHP через FPM/CGI; хостинг перечитывает его до 5 минут). Или строка в `.htaccess`: `php_value auto_prepend_file /home/ЛОГИН/site/antibot-gate/gate.php` (только Apache с mod_php). Или «Настройки PHP» в панели хостинга | любой PHP-сайт. Срабатывает раньше всего, в том числе раньше кэша страниц WordPress. **Неверная строка в `.htaccess` даёт ошибку 500 всему сайту** — сразу откройте сайт и при ошибке уберите строку |
| **Б. WordPress: `mu-plugins`** | скопируйте `mu-plugin-loader.php` в `wp-content/mu-plugins/antibot-gate.php`. Если папка привратника лежит не рядом с корнем сайта, впишите в `wp-config.php` `define('ABG_DIR', '/путь/antibot-gate');` | если `auto_prepend_file` хостинг не даёт. Не видит страницы, которые плагин кэша отдаёт раньше WordPress (WP Super Cache, W3 Total Cache, LiteSpeed Cache): на сайте с кэшем страниц лучше способ А |
| **В. Строка в `index.php`** | первой строкой после `<?php`: `require '/home/ЛОГИН/site/antibot-gate/gate.php';` | OpenCart, самописные сайты. Это правка кода сайта — только с согласия владельца; после обновления движка вписать снова |

Подключить двумя способами сразу не страшно: второй раз привратник не сработает.

4. Проверьте:
   - сайт открывается, в коде страницы перед `</body>` есть `<i id="abm" …>` и `<script src="/?abg=m" async>`;
   - `/?abg=m` отдаёт скрипт;
   - в `antibot-gate/data/log/` появился файл за сегодня и пополняется;
   - корзина, вход, оформление заказа работают.
5. Если хостинг даёт cron — можно добавить раз в минуту `php /home/ЛОГИН/site/antibot-gate/sync.php`. Не обязательно.

## Обновление

Привратник сам не обновляется. Код с сервера защиты не приходит никогда, только списки и настройки. Новую версию ставят вручную, это 5 минут по FTP или SFTP:

1. Скачайте `antibot-gate-X.Y.Z.zip` со страницы релизов репозитория. Что изменилось и насколько это срочно, написано в `CHANGELOG.md` и на странице релиза.
2. Замените в папке `antibot-gate` файлы `gate.php`, `mark.js`, `sync.php`, `data.htaccess`. Если подключали через `mu-plugins` — ещё `wp-content/mu-plugins/antibot-gate.php` из `mu-plugin-loader.php`, но только когда в заметках к версии сказано, что он изменился.
3. **Не заменяйте** `config.php`, `my-rules.php` и папку `data`: в них ваши настройки, правила, ключ сайта, журнал и принятый список. Новые строки настроек, если они нужны, перечислены в заметках к версии. Без них новая версия работает как прежняя.
4. Проверьте:
   - сайт открывается;
   - на странице состояния в шапке новая версия и «Ошибок нет»;
   - или `php antibot-gate/sync.php` печатает `ok`.

Порядок чисел в версии: третья цифра — исправления, вторая — новые возможности. Сервер защиты продолжает работать и со старыми версиями. Если обновление срочное, это сказано первой строкой в заметках к версии.

Откатить обновление — вернуть прежние файлы. `config.php` и `data` вы не трогали, поэтому всё остальное останется как было.

## Откат

Уберите строку способа А / удалите файл из `mu-plugins` / уберите строку `require` — привратник выключен сразу. Папку `antibot-gate` после этого можно удалить.

## Что уходит в хаб

Только **подозрительные адреса за последний час**: с пробами, со страницами без метки сверх порога (`suspect_pages`, 20), с запросами сверх `rate_hour` (600) или с HEAD-запросами сверх `head_hits` (20). По каждому — адрес, счётчики по видам страниц (карточки, разделы, поиск, пробы), есть ли метка, пришёл ли из поиска, до трёх имён браузера и до пяти адресов проб. Плюс общие цифры за час: запросов, адресов, доля страниц с меткой; версии PHP и привратника.

С 0.2.0 ещё: выбор сайта (`shared`); по каждой связке и группе за час — сколько раз сработала, сколько закрыто, сколько адресов и у скольких есть метка, до пяти примеров (адрес, имя браузера, откуда пришёл, страница); свои правила сайта из `my-rules.php` — если в нём `'offer' => true`.

Не уходят: обычные посетители, адреса страниц и поисковые запросы, заказы, корзина, данные покупателей.

## Предохранители

Что бы ни пришло из хаба:
- адреса самого сервера (`server_ips`), белого списка (`allow`) и сетей робота Mail.ru не закрываются; поисковые роботы Яндекса, Google и Bing проверяются по DNS и проходят мимо любого бана;
- сеть шире /16 (IPv6 /48) отбрасывается;
- имя браузера, под которое попадает обычный Chrome, Safari, Firefox или Яндекс Браузер, отбрасывается;
- связка без имени браузера и без Referer (только адрес страницы, метод или «без Referer») отбрасывается — так ходят и люди; связка только по имени, которое задевает обычный браузер, и связка только по Referer, которое задевает обычный переход из Google, Яндекса, Bing, — тоже. Те же проверки — у своих правил сайта;
- если в списке больше `max_new_bans` (10 000) новых записей сверх уже принятых — весь список не принимается, остаётся прежний; первый список после установки принимается целиком;
- хаб не ответил — работает последний принятый список.

## Свой журнал

`data/log/ГГГГ-ММ-ДД.log`, поля через табуляцию: время (unix), адрес, метод, вид запроса (`page`, `product`, `catalog`, `search`, `static`, `js`, `probe`, `sqli`, `other`), адрес страницы (у статики — без параметров), код ответа, метка (1/0), белый список или поисковик (1/0), имя браузера, откуда пришёл, что сработало (с 0.2.0: `!причина` — закрыло запрос, без `!` — только отметка; причины: `@bans`, `@nets`, `@names`, `@seo` — группы общего списка, `own` — свои правила, `local` — сканер на месте, иначе — имя связки).

## Чего привратник не видит

- картинки и стили — их хостинг отдаёт без PHP. Вместо признака «грузил картинки» — метка JS;
- страницы, которые отдаёт кэш nginx или CDN, минуя PHP;
- забаненный запрос всё равно доходит до PHP, но останавливается на первой строке. Против парсеров этого достаточно, против DDoS — нет.

Метка привязана к сети: если у телефона сменился адрес, до суток (пока скрипт не возьмёт метку заново) его страницы считаются «без метки». Поэтому по одной метке привратник никого не закрывает — только записывает.
