# Что нового

Здесь — сторож для сервера (`antibot.py`). У привратника для обычного хостинга (`gate/`) свой журнал изменений — `gate/CHANGELOG.md`, свои версии и релизы (`gate-vX.Y.Z`).

Обновиться: `git pull && sudo ./install.sh`. Настройки (`/etc/antibot/antibot.ini`) и база не меняются.

## 0.2.2 — 26.11.2026

Что нашлось на магазине на WooCommerce: в первую неделю каталог можно было выкачать целиком быстрее, чем срабатывал сторож.

- **WooCommerce: каталог через Store API больше не считается работой браузера.** Раньше любой запрос к `/wp-json/wc/store/` был для сторожа «скриптом страницы», то есть признаком человека. Программа, которая выкачивает каталог через `/wp-json/wc/store/v1/products?per_page=100` (100 товаров с ценами за запрос), выглядела как покупатель. Теперь признак браузера — только корзина, оформление заказа и `batch`.
- **WooCommerce: разделы — ещё `/shop/` и `/catalog/`.** Раньше разделом считалось только `/product-category/` и `/product-tag/`. У многих тем каталог лежит в другой папке, и тогда правила «без скриптов», «парсер», «пагинация» обходчиков каталога не видели.
- **`--check-config` подсказывает, если каталога не видно.** Если карточки и разделы — меньше 5 % страниц в журнале, сторож пишет, какие папки сайта открывают чаще всего, и как вписать свою: `antibot.ini`, раздел `[patterns]`, `catalog = ^/ПАПКА/`. Проверьте это после обновления и после установки на новый сайт.
- **Сам Store API каталога лучше закрыть** — сторож разбирает журнал раз в минуту, а весь каталог через API уходит за секунды. Если витрина не показывает товары скриптом через Store API (блоки «Все товары», «Фильтр по цене»), достаточно одного файла в `wp-content/mu-plugins/`, который для гостей отвечает 404 на `/wc/store/…/products` и `/wp/v2/product` — пример в `README.md`, раздел «WooCommerce».

## 0.2.1 — 26.11.2026

- **Установка через `sudo ./install.sh` снова проходит до конца.** В 0.2.0 установщик останавливался на шаге «файлы nginx» с сообщением «через sudo нельзя … --nginx-files»: сторож принимал запуск через sudo за учётку агента, которой этот шаг запрещён. Сторож, cron и настройки при этом ставились, но страница бана и списки для nginx — нет, поэтому баны до nginx не доходили. Если вы ставили 0.2.0 и видели это сообщение — обновитесь (`git pull && sudo ./install.sh`) и проверьте `sudo antibot --check-config`: строка «nginx: … подключён».
- Ограничение для учётки агента осталось прежним: через `sudo antibot` по-прежнему нельзя `--config`, `--state`, `--replay` и `--nginx-files`.

## 0.2.0 — 20.11.2026

Что сторож выучил за ноябрь на большом сайте. Ботов там стало меньше видно по одному адресу: каталог выкачивают пулы домашних и мобильных прокси, с каждого адреса — одна-две страницы, а имя браузера подделано или скрыто.

**Важно при обновлении.** В режиме наблюдения сторож теперь по-настоящему закрывает не только сканеров, но ещё двоих: подтверждённых за сутки ботов и пулы без скриптов (на 3 часа). Вернуть прежнее «только сканеры» — строка `enforce_always = scan` в `antibot.ini`, раздел `[site]`.

- **Бот подтверждён за сутки.**
  - Адрес получил «закрыл бы» по мягкому правилу: парсер, частота, безголовый браузер, пагинация, HEAD, отказы. За следующие сутки он прислал ещё 20 запросов или больше, и ни одного признака человека. Признаки человека — картинки, значок, скрипты страницы, подсказки, POST, приход из поиска, другие браузеры за адресом. Тогда адрес получает настоящий бан: первый на 7 суток, повтор за 30 суток — на 30.
  - Не подтверждаются: общие адреса людей (VPN), адреса CDN, белый список. Не подтверждаются и адреса, чьё имя браузера уже закрыто в nginx: у пула адрес разовый, потом он достаётся людям.
  - Поддельный поисковик и подбор пароля сюда не входят. Первое при сбое DNS на сервере задело бы настоящего робота, второе — своих сотрудников.
  - На большом сайте за 18 дней правило сработало 8 раз, ошибка одна: человек листал выдачу по 500 строк без картинок. Он увидел страницу бана с контактом.
- **Без скриптов (пул).**
  - Правило срабатывает на адрес под именем обычного браузера, если выполнено всё сразу:
    - за час 20 страниц каталога или больше;
    - ни картинок, ни скриптов страницы, ни подсказок, ни POST;
    - за сутки адрес ни разу не грузил картинки и не приходил из поиска.
  - Такой адрес закрывается по-настоящему на 3 часа. Срок не удлиняется при повторе: домашние адреса пула потом достаются людям.
  - Пять таких банов за час — письмо «пул без скриптов» с сетями и именами браузера.
  - Правило молчит, если картинок сайта почти нет в журнале: их отдаёт CDN или другой домен. Тогда «без картинок» выглядит каждый посетитель.
  - На большом сайте за неделю: пул — 138 адрес-часов, мониторы цен — 8, людей — 0.
- **Пул разовых адресов — письмо.**
  - Условие: за час с одним именем браузера 60 адресов или больше, у каждого 1–6 страниц и ни картинок, ни скриптов. Среди всех адресов с этим именем такие должны быть большинством: у людей с тем же именем картинки грузятся.
  - Правила по адресу такое не видят. Сторож ничего не закрывает, а в письме предлагает варианты: закрыть имя (`--block-ua`) или облачную сеть (`--ban-net`).
  - То же видно в `--daily`, раздел 9.
- **Подделанные имена браузеров.**
  - Признаки подделки:
    - версия Chrome из двух чисел (`Chrome/124.0 Safari/…` вместо `Chrome/124.0.0.0`);
    - `AppleWebKit/537.36` без `(KHTML, like Gecko)`;
    - имя, оборванное после скобки;
    - `HeadlessChrome` в самом имени.
  - Такое имя — признак «за бота» в `--daily` и `--who`, а в разделе 7 сводки есть их список. Сам сторож по нему не закрывает.
- **Браузер без окна по заголовку `Sec-CH-UA`.**
  - Chrome без окна называет себя `HeadlessChrome` в заголовке `Sec-CH-UA`, даже когда программа сменила имя браузера. У людей такого значения нет. nginx отвечает таким запросам страницей бана.
  - Поисковики и проверки скорости страниц проходят.
  - Адресов из белого списка запрет не касается — свои проверки сайта ведите с них.
  - Выключить: `[features] block_headless = no`.
- **Белый список доходит до nginx** (`allow.conf`). Запреты по имени браузера (`--block-ua` и браузер без окна) адреса из `[allow]` и сам сервер больше не задевают.
- **`--ban-net СЕТЬ ЧАСОВ "причина"` — бан сети целиком**, для облаков и хостингов, откуда идёт пул.
  - Сначала команда проверяет журналы за все дни: были ли в сети адреса с признаками человека. Если были — не закрывает; закрыть всё равно можно с `--force`. Люди ходят и через VPN в облаках.
  - Отказывает, если сеть пересекается с белым списком, CDN, VPN людей или сетями поисковиков, и если сеть шире /12.
  - Снять: `--unban СЕТЬ`.
- **Нагрузка сервера.**
  - Средняя нагрузка выше числа ядер дольше 10 минут — одно письмо на эпизод. В нём процессы, запросы к сайту против обычного и самые активные адреса.
  - Резервную копию и обновление системы сторож узнаёт сам и о них не пишет.
  - Эпизоды видны в `--daily` (раздел 10), `--report` и недельной сводке.
  - Порог: `[thresholds] load_max`. Выключить: `[features] load_watch = no`.
- **Писем «работа над ошибками» не больше 12 в сутки, остальных тревог — не больше 50, пределы раздельные.** Раньше в день с ошибками правил письма «закрыл бы зря?» выбирали общий предел, и тревога о выгрузке каталога не уходила.
- **Найдено при проверке:**
  - **«Разных браузеров за адресом» в `--daily` и `--who`** — теперь только имена, под которыми грузились картинки или работали скрипты. Парсер со сменой имён раньше получал «похоже, человек». Теперь у него признак «меняет имя браузера» — то же исправление, что в 0.1.3 для работы над ошибками.
  - **Битрикс: «подбор пароля» — только форма входа.** Это `/bitrix/admin/` без скрипта и `?login=yes`. Раньше любой POST в админку считался подбором пароля, и контент-менеджер с 20 сохранениями за час получал «закрыл бы».

## 0.1.3 — 29.10.2026

Исправления по третьему отзыву того же пилота.

- **Сканер, который меняет имя браузера, больше не «общий адрес».**
  - В «работе над ошибками» другим браузером за адресом считалось любое новое имя после бана. Сканер меняет имя на каждой серии запросов, заходит на главную, вход и регистрацию — и сторож писал «общий адрес: и бот, и люди, ждёт решения».
  - Теперь другой браузер — только имя, под которым после бана грузились картинки, стили, скрипты страницы, подсказки или значок. Так выглядят люди за одним адресом.
  - Если имён без единой картинки и скрипта набралось много, это видно в доводах письма.
- **«Закрыл бы» не прикрывает сканера.**
  - В наблюдении адрес с «закрыл бы» правила до конца срока не пересчитывают. Сканер, который сначала попал под мягкое правило (например, «долбит отказы» из-за своей проверки сайта), дальше пробовал уязвимости без настоящего бана.
  - Теперь пробы с такого адреса считаются дальше. Набрал порог `scan_hits` за час — получает настоящий бан за сканирование, как и все сканеры. В режиме `report` по-прежнему никого не закрывает.

## 0.1.2 — 28.10.2026

Исправления по второму отзыву того же пилота.

- **Нет ложной тревоги «сайт отдал служебный файл» на страницах входа.**
  - Битрикс на любой адрес `/bitrix/admin/*.php` и на всё внутри `/auth/` отвечает кодом 200 и страницей входа. Сканер спрашивает `/bitrix/admin/phpinfo.php`, а сторож писал «проверить сегодня, нет ли паролей».
  - Шаблоны утечек теперь смотрят на конец пути: `/auth/.env/` — страница сайта, а не файл. `.env.local` и `.env.production` по-прежнему тревога.
  - Исключения для утечек (`leak_exclude`) можно задать в наборе движка. У Битрикса — `^/bitrix/admin/` и `^/auth/`.
  - Свои исключения добавляйте в `antibot.ini`, раздел `[patterns]`, ключом `leak_exclude_extra`. Ключ `leak_exclude` без `_extra` заменяет набор движка целиком, как и у других шаблонов.
  - В письме об утечке написано, как убрать ложную тревогу.
- **Длинный хвост после ротации.** Если хвост прежнего файла больше 64 МБ, сторож дочитывает его за несколько проходов и только потом переходит на новый файл. Раньше остаток пропадал.

## 0.1.1 — 28.10.2026

Исправления по первому отзыву пилота (магазин на 1С-Битрикс, BitrixVM).

- **Mail.ru больше не «поддельный поисковик».**
  - У роботов Mail.ru (`Mail.RU_Bot`) нет имени в DNS, поэтому проверка по DNS их не подтверждала.
  - Теперь адреса из сетей VK считаются настоящим роботом: 95.163.32.0/19, 90.156.232.0/21, 217.174.190.0/23 (раздел `[se_nets]` в `rules.txt`).
  - «Mail.ru» без имени в DNS с другого адреса — «проверить нечем», а не подделка. Общие правила на него действуют: парсер, частота, пробы.
  - Всей сети VK (AS47764) сторож не доверяет: в ней облако, где адрес арендует кто угодно.
  - Если на адреса VK уже записаны «закрыл бы», сторож снимет их сам при работе над ошибками.
- **`--who` и `--daily`** для подтверждённого поисковика пишут «настоящий поисковик — не трогать». Раньше `--who` писал «DNS это не подтвердил» даже для проверенного Googlebot.
- **BitrixVM:**
  - **файл nginx.** nginx на BitrixVM не читает `conf.d`. Установка проверяет по `nginx -T`, подключён ли файл уровня http, и на BitrixVM кладёт его в `/etc/nginx/bx/maps/antibot.conf`. Новый путь она записывает в `antibot.ini` (`[paths] nginx_http_conf`) — это единственная настройка, которую меняет обновление. Если файл не подключён и выбрать папку не удалось, установка останавливается и объясняет, что делать, а не откатывает `--vhost`;
  - **формат журнала.** Готовый формат `log_format = bitrixvm`: код ответа стоит до запроса, время ответа — в скобках с датой. При новой установке распознаётся сам.
- **Ротация с датой** (`access.log-20261028`, logrotate `dateext`):
  - после ротации сторож находит прежний файл по inode и дочитывает его хвост;
  - архивы с датой видны в `--daily 168`. Шаблон архивов по умолчанию — `access.log[.-]*`, прежнее значение `access.log.*` сторож понимает так же.
- `--check-config` показывает, читает ли nginx файлы AntiBot.
- `--remove` удаляет файлы nginx по путям из настроек.

## 0.1.0 — 28.10.2026

Первая версия, идёт пилот.

- **Сторож:**
  - закрывает сканеров уязвимостей сам, в том числе за SQL-инъекции в поиске;
  - находит парсеров каталога, безголовые браузеры, глубокую пагинацию, `HEAD` по страницам, подбор пароля, слишком частых, поддельных поисковиков и ИИ-ботов;
  - по умолчанию работает в режиме наблюдения.
- **Сводки для разбора:** `--daily` (за сутки, с кандидатами в бан и доводами), `--who` (что делал адрес), `--block-ua` (бан по точному имени браузера с проверкой, нет ли под ним людей).
- **Наборы шаблонов:** свой движок, Next.js, 1С-Битрикс, OpenCart, WooCommerce.
- **Рабочая папка `workspace/`** для ежедневного разбора с Claude Code, Codex или ChatGPT.
- **Проверка:** прогон по журналам большого сайта за 12 дней (~5 млн запросов). Сканеры и подделки под поисковики совпали с проверенным сторожем этого сайта адрес в адрес.
