# Что нового

Обновиться: `git pull && sudo ./install.sh`. Настройки (`/etc/antibot/antibot.ini`) и база не меняются.

## 0.1.2 — 28.10.2026

Исправления по второму отзыву того же пилота.

- **Нет ложной тревоги «сайт отдал служебный файл» на страницах входа.**
  - Битрикс на любой адрес `/bitrix/admin/*.php` и на всё внутри `/auth/` отвечает кодом 200 и страницей входа. Сканер спрашивает `/bitrix/admin/phpinfo.php`, а сторож писал «проверить сегодня, нет ли паролей».
  - Шаблоны утечек теперь смотрят на конец пути: `/auth/.env/` — страница сайта, а не файл. `.env.local` и `.env.production` по-прежнему тревога.
  - Исключения для утечек (`leak_exclude`) можно задать в наборе движка. У Битрикса — `^/bitrix/admin/` и `^/auth/`.
  - Свои исключения добавляйте в `antibot.ini`, раздел `[patterns]`, ключом `leak_exclude_extra`. Ключ `leak_exclude` без `_extra` заменяет набор движка целиком, как и у других шаблонов.
  - В письме об утечке написано, как убрать ложную тревогу.
- **Длинный хвост после ротации.** Если хвост прежнего файла больше 64 МБ, сторож дочитывает его за несколько проходов и только потом переходит на новый файл. Раньше остаток пропадал.

## 0.1.1 — 28.10.2026

Исправления по первому отзыву пилота (магазин на 1С-Битрикс, BitrixVM).

- **Mail.ru больше не «поддельный поисковик».**
  - У роботов Mail.ru (`Mail.RU_Bot`) нет имени в DNS, поэтому проверка по DNS их не подтверждала.
  - Теперь адреса из сетей VK считаются настоящим роботом: 95.163.32.0/19, 90.156.232.0/21, 217.174.190.0/23 (раздел `[se_nets]` в `rules.txt`).
  - «Mail.ru» без имени в DNS с другого адреса — «проверить нечем», а не подделка. Общие правила на него действуют: парсер, частота, пробы.
  - Всей сети VK (AS47764) сторож не доверяет: в ней облако, где адрес арендует кто угодно.
  - Если на адреса VK уже записаны «закрыл бы», сторож снимет их сам при работе над ошибками.
- **`--who` и `--daily`** для подтверждённого поисковика пишут «настоящий поисковик — не трогать». Раньше `--who` писал «DNS это не подтвердил» даже для проверенного Googlebot.
- **BitrixVM:**
  - **файл nginx.** nginx на BitrixVM не читает `conf.d`. Установка проверяет по `nginx -T`, подключён ли файл уровня http, и на BitrixVM кладёт его в `/etc/nginx/bx/maps/antibot.conf`. Новый путь она записывает в `antibot.ini` (`[paths] nginx_http_conf`) — это единственная настройка, которую меняет обновление. Если файл не подключён и выбрать папку не удалось, установка останавливается и объясняет, что делать, а не откатывает `--vhost`;
  - **формат журнала.** Готовый формат `log_format = bitrixvm`: код ответа стоит до запроса, время ответа — в скобках с датой. При новой установке распознаётся сам.
- **Ротация с датой** (`access.log-20261028`, logrotate `dateext`):
  - после ротации сторож находит прежний файл по inode и дочитывает его хвост;
  - архивы с датой видны в `--daily 168`. Шаблон архивов по умолчанию — `access.log[.-]*`, прежнее значение `access.log.*` сторож понимает так же.
- `--check-config` показывает, читает ли nginx файлы AntiBot.
- `--remove` удаляет файлы nginx по путям из настроек.

## 0.1.0 — 28.10.2026

Первая версия, идёт пилот.

- **Сторож:**
  - закрывает сканеров уязвимостей сам, в том числе за SQL-инъекции в поиске;
  - находит парсеров каталога, безголовые браузеры, глубокую пагинацию, `HEAD` по страницам, подбор пароля, слишком частых, поддельных поисковиков и ИИ-ботов;
  - по умолчанию работает в режиме наблюдения.
- **Сводки для разбора:** `--daily` (за сутки, с кандидатами в бан и доводами), `--who` (что делал адрес), `--block-ua` (бан по точному имени браузера с проверкой, нет ли под ним людей).
- **Наборы шаблонов:** свой движок, Next.js, 1С-Битрикс, OpenCart, WooCommerce.
- **Рабочая папка `workspace/`** для ежедневного разбора с Claude Code, Codex или ChatGPT.
- **Проверка:** прогон по журналам большого сайта за 12 дней (~5 млн запросов). Сканеры и подделки под поисковики совпали с проверенным сторожем этого сайта адрес в адрес.
