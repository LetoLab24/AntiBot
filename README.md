# AntiBot

Сторож от вредных ботов для сайта на nginx.

Раз в минуту AntiBot читает журнал запросов сайта:
- **сканеров уязвимостей закрывает сам** — тех, кто ищет `/.env`, `/.git`, резервные копии или пробует SQL-инъекции;
- **парсеров каталога, слишком частых и поддельных поисковиков записывает** как «закрыл бы» — кого закрывать, решаете вы;
- **поисковики не трогает:** Яндекс, Google, Bing и Mail.ru проверяет по DNS.

Закрытый адрес получает от nginx страницу «Доступ временно ограничен» с вашим контактом — до сайта и базы запрос не доходит.

Разбирать подозрительных удобно с ИИ-агентом: Claude Code или Codex в VS Code. Агент снимает сводку, проверяет каждого кандидата, предлагает, кого закрыть, и закрывает только после вашего «да».

Версия 0.1.0 — первая, идёт пилот на нескольких сайтах. Нашли ошибку или бот прошёл мимо — напишите в Issues.

## Что нужно

- Linux-сервер (VPS/VDS) с nginx и правами root.
- Python 3.6 или новее. Он есть почти везде, ничего доустанавливать не нужно.
- cron и почтовый ящик, с которого сторож будет слать письма (SMTP).

Grafana, базы данных и внешние сервисы не нужны. Сторож никуда не отправляет ваши данные. Наружу он ходит только за DNS-проверкой поисковиков и раз в сутки — за опубликованными списками адресов OpenAI и Perplexity (это можно выключить).

**Обычный хостинг без root:** если есть SSH, Python 3.6+ и доступ к журналу, сторож работает в режиме `report` — сводки и письма без банов. **Конструкторы сайтов** (Tilda, InSales и т. п.) журналов не дают — там AntiBot не поставить.

## Установка

1. Скачайте: `git clone https://github.com/LetoLab24/AntiBot.git && cd AntiBot`
2. Поставьте: `sudo ./install.sh --vhost /etc/nginx/sites-enabled/ВАШ_САЙТ.conf`
   - `--vhost` подключает страницу бана: делает бэкап файла, проверяет `nginx -t` и при ошибке возвращает файл как был;
   - без `--vhost` строку `include /etc/nginx/snippets/antibot-site.conf;` нужно вписать в `server { }` самому.
3. Откройте `/etc/antibot/antibot.ini` и впишите домен, почту, контакт для страницы бана и движок сайта (`engine`). Адреса сервера и путь к журналу установка подставит сама.
4. Проверьте:
   - `sudo antibot --check-config` — журнал читается, движок распознан;
   - `sudo antibot --test-mail` — письмо пришло.
5. Готово. Сторож запускается из cron раз в минуту.

Ставить через ИИ-агента — вставьте ему `PROMPT.md`.

## Первая неделя — наблюдение

Сторож закрывает только сканеров. Остальных он записывает и пишет вам, если что-то срочное: тяжёлый парсер, утечка служебного файла, всплеск запросов.

| Письмо | Что делать |
|---|---|
| «работа над ошибками — закрыл бы зря?» | сторож сам проверяет свои решения. Явные ошибки снимает сам, по остальным предлагает — решите вы |
| «ВНИМАНИЕ, сайт отдал служебный файл» | проверить в тот же день: что за файл и нет ли в нём паролей |
| «сводка за неделю» (по воскресеньям) | прочитать первый абзац — там вывод и нужно ли что-то делать |

Посмотреть самому: `sudo antibot --daily` — сводка за сутки с кандидатами в бан.

## Ежедневный разбор с агентом

Скопируйте папку `workspace/` к себе на компьютер. Заполните `server.md` (как зайти на сервер), откройте папку в VS Code с Claude Code или Codex и напишите «сторож — ежедневно». Агент работает по `CLAUDE.md` и `DAILY.md`, а признаки бота и человека берёт из `HOWTO-BOTS.md`.

Безопаснее дать агенту отдельную учётку, которой разрешена только команда `antibot`: `sudo ./install.sh --agent-user antibot-agent`.

Без агента: вставьте в ChatGPT `workspace/DAILY.md`, `workspace/HOWTO-BOTS.md` и вывод `sudo antibot --daily`.

## Команды

```
sudo antibot --daily                  сводка за сутки (--daily 168 — за неделю)
sudo antibot --who АДРЕС              что делал адрес
sudo antibot --ban АДРЕС ЧАСОВ "причина"
sudo antibot --unban АДРЕС            снять бан
sudo antibot --allow АДРЕС "кто это"  снять бан и больше не трогать
sudo antibot --block-ua "имя"         закрыть точное имя браузера (сначала проверит, нет ли под ним людей)
sudo antibot --mode enforce           включить настоящие баны по всем правилам
sudo antibot --mode observe           вернуть наблюдение
```

## Как включить настоящие баны

Через неделю наблюдения, если писем «закрыл бы зря?» не было или по ним всё ясно: `sudo antibot --mode enforce`. Записанные «закрыл бы» станут настоящими банами. Пороги правил можно поправить в `antibot.ini`, раздел `[thresholds]`.

## Обновление и удаление

Мы обновляем правила и сторож, когда видим новых ботов: новые пробы уязвимостей, новые почерки парсеров. Что изменилось — в `CHANGELOG.md`.

- Обновить: `git pull && sudo ./install.sh` — настройки и база не меняются.
- Удалить: `sudo ./install.sh --remove`. Строки `include` уберутся из сайта, nginx перечитается. Настройки и база останутся; `--purge` удаляет и их.
