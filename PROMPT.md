# Промпт: поставить AntiBot на сервер

Скопируйте всё ниже черты в Claude Code, Codex или другой ИИ-агент, у которого есть терминал с доступом к серверу: VS Code с Remote-SSH или `ssh` с вашего компьютера.

---

Поставь сторож AntiBot (https://github.com/LetoLab24/AntiBot) на мой сервер с сайтом. Работай по шагам, показывай, что делаешь. **Любое изменение файлов вне AntiBot делай только после моего «да».**

1. **Осмотрись (только чтение):**
   - ОС и версия, `python3 -V` (нужен 3.6+), `nginx -v`;
   - есть ли панель управления (ISPmanager, FastPanel, Hestia, BitrixVM, aaPanel);
   - где конфиг моего сайта (`nginx -T | grep -n server_name`) и где его журнал запросов (`access_log`), формат журнала;
   - стоит ли сайт за Cloudflare или другим прокси. Если да — проверь, что nginx видит настоящие адреса посетителей (`set_real_ip_from` / `real_ip_header`). Если нет — остановись и скажи мне: без этого сторож закроет прокси вместо ботов.
   - Расскажи, что нашёл.
2. **Скачай и поставь:**
   ```
   git clone https://github.com/LetoLab24/AntiBot.git /root/AntiBot
   cd /root/AntiBot && sudo ./install.sh
   ```
   Пока без `--vhost`. Установка ставит сторожа в режиме наблюдения и ничего не закрывает, кроме сканеров уязвимостей — и то только после подключения к сайту.
3. **Настрой `/etc/antibot/antibot.ini`:**
   - `domain`, `contact` (контакт для страницы бана — спроси у меня);
   - `[mail]`: куда слать письма и с какого ящика (спроси у меня, пароль впиши сам, не показывай его в чате);
   - `engine`: `bitrix`, `opencart`, `woocommerce`, `nextjs` или `custom` — определи по сайту;
   - `log_format`: `combined` подходит почти всем; BitrixVM установка распознаёт сама (`bitrixvm`). Свой формат — `custom` и `log_regex`;
   - в `[allow]` — мои адреса (офис, дом) и адреса сервисов, которым я сам отдаю данные (агрегаторы, маркетплейсы; спроси у меня).
4. **Проверь:**
   - `sudo antibot --check-config` — журнал читается, доля «товар / раздел / обычные страницы» правдоподобна. Если почти всё «прочее» — подбери шаблоны в `[patterns]`;
   - `sudo antibot --test-mail` — я получил письмо.
5. **Подключи страницу бана к сайту.** Покажи мне, в какой файл и куда встанет строка `include /etc/nginx/snippets/antibot-site.conf;`. После «да»: `sudo ./install.sh --vhost ФАЙЛ`. Если сайт создан в панели — не правь файл панели, а положи строку в место для своих настроек, которое панель не перезаписывает, и скажи мне куда.
6. **Проверь страницу бана:** `sudo antibot --ban <тестовый адрес из 203.0.113.x> 0.1 "проверка"` → `grep 203.0.113 /etc/nginx/antibot/banned.conf` → `sudo antibot --unban <тот же адрес>`. Свой адрес не закрывай.
7. **Агент для ежедневного разбора (по желанию):** `sudo ./install.sh --agent-user antibot-agent` — учётка, которой по sudo можно только `antibot`. Помоги положить мой SSH-ключ в `~antibot-agent/.ssh/authorized_keys` и запись `Host` в мой `~/.ssh/config`.
8. **Итог:** что поставлено, где настройки, что я буду получать письмами, как открыть `workspace/` для ежедневного разбора. Режим `enforce` не включай — первая неделя только наблюдение.

**Запреты:**
- не трогать конфиги других сайтов и служб;
- не перезапускать nginx без `nginx -t`;
- не закрывать мой адрес и адреса поисковиков;
- не отправлять журналы и адреса посетителей никуда.
